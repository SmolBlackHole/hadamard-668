## Decision

The measured alternatives do not justify a new solver default. Keep experimental
proposal selection and equal-Q adoption opt-in. The reusable deliverables are the
paired experiment runner, exact neighborhood diagnostics and expanded named-group
classification, rather than a demonstrated increase in solve rate.

## Recovered history

`research-archive/README.md` in the repository root indexes 33 recovered original
Markdown files, 300,699 bytes in total. They are exact Git blobs with a provenance
manifest and checksums, ignored separately from maintained documentation.

The mature snapshot comes from `dd287a9`, before the documentation rebuild at
`662ec00`. Original research, early Turyn notes and intermediate audits are also
preserved. Some early formulas were corrected later; follow the archive index.

Historical notes already rejected selecting kick starts solely by immediate Q.
This round treats that as a negative control, not a new proposed discovery.
Turyn multiplication and Turyn-type sequences are distinct concepts. The
[Balonin and Djokovic paper](https://arxiv.org/abs/1508.00640) describes the extension
of Golay multiplication to negaperiodic pairs; no novelty claim is made here.

## Search experiments

All screens use random starts, seeds 42..341, n=40,46,50 and 6,000,000 candidate
evaluations per run. Every solved candidate passes the existing independent
pipeline verification. The previous [quench allocation experiment](quench-allocation.md)
is retained rather than rerun.

The randomized and residual-ranked arms share the same proposal sampling rule.
Residual ranking additionally charges every full-Q score to the outer candidate
budget. Compare memory and walk-length controls against no-targeted, because
nested quenches intentionally retain default settings.

### Equal-Q adoption screen

Four arms, 3,600 runs total, on the same screen instances.

| Arm | n=40 | n=46 | n=50 |
| --- | ---: | ---: | ---: |
| default | 31 | 0 | 1 |
| tabu_accept_equal=true | 31 | 1 | 0 |
| no-targeted | 22 | 0 | 0 |
| no-targeted, tabu_accept_equal=true | 22 | 0 | 0 |

Equal adoption retains a changed equal-best snapshot and continues searching from
it. Strict improvement counters remain unchanged. This option affects outer walks;
nested quenches continue to use their existing default configuration.

No screen winner was selected, so a disjoint-seed confirmation was not run and
no default was promoted. Tied or near-tied counts do not establish equivalence.

## Mathematical diagnostics

The recorded sweep contains 162 Q=1 endpoints among run IDs 301..6300. Exact
diagnostics found no single-flip, two-flip, distinct-sequence three-flip or
one-flip-per-sequence four-flip repair. The completeness boundary matters:
restricted move families must not be presented as unrestricted Hamming balls.

A follow-up exhausted the remaining three-flip cases by taking each same-row
pair and evaluating every remaining single flip through the updated exact tracker.
It found no repair in any endpoint. Thus all 162 observed endpoints have Hamming
distance at least four from any solution. Any direct four-flip repair would need
at least two flips in the same sequence; unrestricted quadruples were not exhausted.
This is a finite dataset result, not a theorem about every Q=1 state.

All 249 valid stored solution records were independently verified. The additional
classification uses the group generated by independent negashifts, independent
reversals, row permutations and common unit decimation modulo 2n. It merges none
of the stored quick classes: 100 at n=32, 91 at n=34, 52 at n=36, 3 at n=46,
and one each at n=48,50,52.

In Z[z]/(z^n+1), substitution z -> z^k for gcd(k,2n)=1 is a signed permutation
of coefficients. It commutes with the involution z -> z^-1, so it permutes the
autocorrelation residual coefficients up to sign and preserves Q. It normalizes
the existing shift/reversal actions. Enumerating the units and choosing the minimum
quick representative therefore canonicalizes this specified generated group.
Tests check odd and even lengths, energy invariance and hash invariance under the
generators. This is not unrestricted Hadamard row/column equivalence.

Full matrix equivalence is not needed to explain the absence of additional solves
in these screens. Existing database identities have not been replaced.

## Reproduction

Use the ablation runner's `--configs` option with JSON objects corresponding to the
override table above. The local files are:

- `runs/research/search-screen-configs.json` and `search-screen.json`;
- `runs/research/equal-screen-configs.json` and `equal-screen.json`;
- `runs/research/geometry.json` for the exact endpoint and orbit diagnostics.

```bash
python -m lab.compare --configs runs/research/search-screen-configs.json \
  --n 40 --n 46 --n 50 --seeds 300 --seed-start 42 \
  --candidate-budget 6000000 --workers 12 --output runs/research/search-screen.json
python -m lab.compare --configs runs/research/equal-screen-configs.json \
  --n 40 --n 46 --n 50 --seeds 300 --seed-start 42 \
  --candidate-budget 6000000 --workers 12 --output runs/research/equal-screen.json
python -m lab.neighborhoods --first-run-id 301 --last-run-id 6300 \
  --database data/hadamard.db --output runs/research/geometry.json
```

Raw reports and config files are local ignored artifacts, not shipped datasets.
Reports record effective settings and source fingerprints. Geometry diagnostics
also fingerprint their selected database records. The local input database is
required to reproduce those diagnostics; arbitrary fresh data need not reproduce
these counts. Experiments used Python 3.13.14 on Windows with locked dependencies.

## Interpretation and limits

The solver reaches low residual energy without necessarily approaching a solution
in Hamming distance. For different sequences, flip residuals add exactly; repeated
flips within one sequence have interaction corrections and must be scored exactly.
Neither energy alone nor a restricted orbit count captures basin reachability.

The hard lengths yielded too few solutions for a robust ranking. Some mathematical
diagnostics overlapped the first screen, and arms ran in sequential blocks. Timing
figures from that screen are not evidence of a speed advantage. Equal-Q screening
ran after the other CPU work ended, but its sparse solve counts still limit inference.

The recursive `construct` budget-accounting limitation remains documented in
[Constructions](constructions.md#recursive-budget-limitation). These `gs4` experiments
do not exercise that path.

Final validation: 157 tests passed, Ruff passed, Pyright reported no errors or
warnings, and maintained local documentation links and anchors resolved. Across
the two screens, 900 default and 900 no-targeted runs reproduced identical final
energies, candidate counts and solved-state hashes, despite adding the opt-in
equal-Q feature between screens.
